문제 1 · Ch1: HIPM & Big Three (70점)

상황: 최근 출시된 차량용 인포테인먼트 터치스크린 시스템 조작 중 전방 주시 태만으로 인한 추돌 사고가 급증하고 있다. 제조사는 터치 반응 속도를 높였음에도 사고율 감소 효과를 얻지 못했다. "내비게이션 조작 중 추돌"과 "음악 조작 중 추돌"은 조작 행위는 다르지만, 분석에서는 둘 다 시선 분산이라는 상위 범주로 묶을 수 있다.

문항 1-1. 인간 정보 처리 모형(Human Information Processing Model; Wickens et al., 2022)의 4단계를 적용하여, 현재 시스템의 병목(Bottleneck)이 발생하는 단계를 특정하고 그 인지적 원인을 분석하시오. (30점)
문항 1-2. 해당 시스템의 UI를 인간 수행의 3대 지표 중 '정확성(Accuracy)'과 '주의 요구량(Attentional Demand)' 측면에서 정량적으로 평가하기 위한 실험 설계(독립변인, 종속변인, 측정 방법)를 구체적으로 제안하시오. (40점)

문항 1-1 전략 — 병목 단계 특정

핵심 열쇠: "터치 반응속도를 높였는데 사고가 안 줄었다" → 제조사는 Response Execution 단계만 건드렸다. 병목은 훨씬 앞에 있다.

HIPM 4단계 매핑표

단계기능이 시나리오에서
① 감각처리 + STSS시각·청각 신호 수용 (~1초 유지)전방 도로 + 화면 → 두 시각 신호 동시 입력
② 지각 (Perception)감각 신호에 의미 부여 (LTM 기반)병목 ①: 전방 도로 지각과 화면 아이콘 지각이 동일 시각 자원 경쟁
③ 작업기억/인지정보 일시 보관 + 의사결정 준비병목 ②: 내비 경로 + 운전 상황 동시 유지 → WM 용량 초과
④ 반응선택 → 반응실행행동 선택 + 근육 제어제조사가 개선한 부분 — 병목이 앞 단계에 있으면 무의미

병목 논증 구조

주장: 병목은 ② 지각(Perception) 단계의 Attention Filter 실패
      + ③ 작업기억(WM) 자원 고갈

논거:
Attention = Filter(선택) + Fuel(자원) — Wickens & McCarley (2008)
운전 → 시각 공간적 주의를 지속 요구 → Filter가 전방 고정
터치스크린 → 동일한 시각 공간 채널 요구
⟹ 두 과제가 같은 Fuel을 경쟁 → 자원 고갈 → 지각 오류 발생
Response Execution 개선은 이 자원 경쟁을 해결하지 못함

Accuracy와 Attentional Demand는 측정법이 다르다. 각각 IV·DV·측정법을 명확히 분리해서 서술해야 한다.

문제 2 · Ch2: SDT, d'/β, Likelihood Alarms (70점)

상황: A 기업은 AI 기반 보안 모니터링 시스템을 도입하였다. 미탐(Miss) 방지를 위해 매우 낮은 임계값을 유지하도록 설계되어 빈번한 오경보(False Alarm)를 발생시키고 있다. 보안 관리자는 초기에 엄격히 대응했으나, 오경보 누적으로 경보를 불신하게 되었으며, 긴급한 실제 위협 경보조차 "단순 오류"로 무시하는 양치기 소년 효과(Cry wolf syndrome; Wickens et al., 2022)를 보이고 있다.

문항 2-1. 관리자의 행동 변화를 신호 탐지 이론(SDT)의 민감도(d')와 판단 기준(β) 개념을 설명하고 이를 활용하여 수리적·인지적 기제로 설명하시오. 특히 오경보 남발이 d'를 변화시킨 것인지, 아니면 β의 이동을 유발한 것인지 핵심 기제를 명확히 논하시오. (35점)
문항 2-2. Sorkin(1989)의 연구에 기반하여 이분법적(Binary) AI 알람 방식을 대체할 수 있는 우도 알람(Likelihood Alarms)의 개념을 정의하시오. 또한 AI 분석 위험 확률에 따라 관리자가 직관적으로 대응 우선순위를 판단할 수 있도록, 시각적·청각적 요소를 결합한 구체적인 'AI 보안 관제 인터페이스' 설계안을 제시하시오. (35점)

문항 2-1 전략 — 핵심 논쟁: d' vs β

결론 먼저: 오경보 남발이 변화시킨 것은 β(판단 기준)의 이동이다. d'는 변하지 않는다.

개념 정의

개념정의이 시나리오에서
d' (민감도)신호 분포와 잡음 분포의 평균 거리 (표준편차 단위)AI 경보 시스템의 신호 품질 — 시스템이 설계된 이상 관리자 경험으로 바뀌지 않음
β (판단 기준)X_C 지점에서 신호분포 높이 / 잡음분포 높이의 비율관리자가 "경보에 반응할 것인지" 결정하는 내부 임계값 → 학습으로 이동 가능

d'는 변하지 않는다 — 논거

d'는 AI 시스템이 진짜 위협과 정상 업무 활동을 통계적으로 구분하는 물리적 품질이다. 관리자의 경험 축적과 무관하게, 시스템의 임계값(threshold)이 낮게 설정된 이상 신호/잡음 분포의 분리도 자체는 변하지 않는다 (Wickens et al., 2022).

β가 이동하는 수리적·인지적 기제

초기 (오경보 드묾):
  관리자 β 낮음 (liberal) → 경보 울리면 즉각 대응

오경보 누적 후:
  P(실제위협 | 경보) 가 매우 낮다고 학습됨
  → 주관적 P(S) ↓
  → β_opt = P(N)/P(S) × [V(CR)+C(FA)] / [V(H)+C(M)]
  → P(N)/P(S) 급증 → β_opt 상승
  → 관리자 β 우측 이동 (conservative)
  → 진짜 위협 경보도 기준 아래 → Miss 발생

ROC 곡선 해석:
  d' 동일한 등감도선(isosensitivity curve) 위에서
  오른쪽으로 이동 → P(H)↓ P(FA)↓ 동시 발생

문항 2-2 전략 — Likelihood Alarms 설계

Binary 방식Likelihood Alarms (Sorkin, 1989)
정보 형태경보 / 비경보 (0 또는 1)위험 확률 연속값 (예: 20%, 60%, 95%)
관리자 행동β 하나로만 반응 → 최적 대응 불가확률 수준별로 다른 β 적용 → 최적 행동 가능
Cry wolf 해결낮은 임계값 → 모든 경보 동일 취급 → 무시낮은 확률 경보는 무시, 높은 확률만 대응

AI 보안 관제 인터페이스 설계안

시각 요소:
  - 색상 그라디언트: 녹색(~20%) → 황색(20~50%) → 주황(50~80%) → 적색(80%+)
  - 경보 카드 크기: 위협 확률 비례하여 증가
  - 확률 수치 명시: "위협 확률 87%" 직접 표시
  - 히스토리 표시: 동일 IP 반복 이상 행동 이력 병기

청각 요소:
  - 20% 미만 → 무음
  - 50% 이상 → 낮은 단음 알림
  - 80% 이상 → 높은 주파수 반복 경고음 + 음성("즉각 확인 요망")

레이아웃:
  - 높은 확률 경보 → 화면 중앙/상단 (Salience↑, Effort↓)
  - 낮은 확률 경보 → 사이드바 격리

문제 3 · Ch3: SEEV, PCP (70점)

상황: 연세대학교의 learnUs 플랫폼은 강의 자료 공유, 과제 제출, 실시간 알림 등 방대한 기능을 제공하고 있다. 그러나 최근 대학원생과 교수들이 중요한 학사 경고나 과제 마감 알림, 긴급 공지사항을 확인하지 못해 행정적 차질을 빚는 사례가 빈번하다. 사용자들은 "화면에 정보가 너무 많아 무엇이 중요한지 모르겠다"거나 "알림이 떴는지조차 몰랐다"는 피드백을 제시하고 있다.

문항 3-1. 공학심리학 전공자로서 learnUs의 인터페이스를 LMS로서 UX와 기능을 분석 평가하시오. 또한 사용자가 "중요 알람을 놓치는 현상"을 SEEV(Salience, Effort, Expectancy, Value) 모델의 4가지 요인을 기준으로 분석하고, 이를 상향식(Bottom-up)과 하향식(Top-down) 기제로 분류하여 논리적으로 설명하시오. (35점)
문항 3-2. Wickens와 Carswell(1995)이 제안한 근접 호환성 원칙(PCP)에 근거하여, 사용자가 학습 콘텐츠에 집중하고 있는 전방 주시(Focused attention) 상태를 방해하지 않으면서도 시스템 경고를 즉각 인지할 수 있도록 돕는 '시각적 유도 및 디스플레이 설계 방안'을 구체적으로 제시하시오. UX, UI 디자인을 고려하여 기능을 어떻게 업그레이드하는 게 대학원생들에게 활용을 잘하게 만드는지 의견을 제시하시오. (35점)

문항 3-1 전략 — SEEV 분석

SEEV 공식 먼저 제시:
SEEV = wS·Salience + wE·(−Effort) + wEx·Expectancy + wV·Value

Bottom-up / Top-down 분류 — 채점 핵심

요인방향learnUs 문제
S (Salience)Bottom-up알림 배지 작음, 깜빡임 없음, 강의 콘텐츠와 색상 대비 낮음 → 시각적 돌출 실패
E (Effort)Bottom-up알림 아이콘 위치 = 화면 우상단 → 시선 중심(콘텐츠)에서 각도 이탈 큼 → 이동 비용↑
Ex (Expectancy)Top-down평소 알림이 드물고 대부분 덜 중요 → 중요 알림이 올 것이라는 기대 낮음
V (Value)Top-down이전 알림 클릭 시 "별 내용 없었다"는 반복 경험 → 알림에 할당하는 주관적 가치 낮음
learnUs UX 서두 추천: "learnUs는 강의자료 열람, 과제 제출, 공지 알림을 단일 플랫폼에 통합한 LMS로서 기능적 완결성은 높으나, 정보 밀도 과다(information overload)와 알림 계층 미분화로 인해 다음과 같은 인지공학적 문제를 보인다."
형모님은 learnUs 대학원생 사용자다. "과제 마감 하루 전, 공지사항 5개 중 어느 것이 마감 알림인지 바로 보이지 않았다" — 이것이 S(Salience) 실패 + V(Value) 저하의 실제 사례다. 직접 경험 쓰면 된다.

문항 3-2 전략 — PCP 설계

PCP 원리 먼저 정의: 동시에 처리해야 하는 정보는 디스플레이 상에서 근접하게 배치해야 한다. 전방 주시 과제에서는, 경고 정보를 초점 영역에 통합하거나 주변시(peripheral vision)로 인지 가능하게 설계해야 한다 (Wickens & Carswell, 1995).

구체 설계 방안

1. 콘텐츠 근접 경고 오버레이 (PCP 핵심)
   강의 영상/PDF 화면 모서리에 긴박도 바 삽입
   → 초점 이동 없이 주변시로 경고 수준 인지
   → "마감 2시간 전" → 상단 가장자리 오렌지 바 등장

2. Ambient 주변시 알림 (Focal 방해 없이)
   화면 전체 테두리가 서서히 색 변화 (무채색 → 주황 → 적색)
   → 초점 콘텐츠 유지 + 주변시가 변화 감지
   → Salience↑, Effort 최소화

3. 중요도 계층 분리 (Value 신뢰 회복)
   긴급(학사경고, 24h 이내 마감) vs 일반(강의자료 업로드) 완전 분리
   → 긴급 = 전체화면 팝업 / 일반 = 사이드바
   → 알림 클릭 = 항상 중요한 내용 → Value 기대 상승

대학원생 활용도 향상 UX 의견

Unitization + Tall Man Lettering 핵심

Unitization (자동화): 반복 경험으로 하위 단위들이 하나의 처리 단위로 묶이는 현상. 노년층은 단어 전체를 하나의 단위로 처리하는 경향이 강해짐 (Allen et al., 2002) → word shape에 의존.

→ 소문자가 대문자보다 word shape 다양성이 커 구별이 쉬움 (Vartabedian, 1972). 의약품 라벨에서 약명은 소문자 중심으로 표기.

Tall Man Lettering (Gerret et al., 2011): 유사 약물명의 차별화 부분을 대문자로 강조.

예) amiLODIPine vs AMiodArone — 시각 특징 차별화로 혼동 오류 감소

   - 상태를 단순 아이콘으로 표시 (✓ 복용 / ✗ 미복용)

② SA Level 2 지원 (이해 촉진)
   - "지금 드신 약과 저녁에 드실 약이 함께 복용하면 안 됩니다"
   - 텍스트 + 충돌 경고 아이콘 (Complementarity)
   - 부정문 피하기: "함께 복용 금지" > "함께 복용하지 마세요"

③ SA Level 3 지원 (예측 + 가족 알림)
   - 복용 패턴 분석: "최근 7일간 오후 약을 4회 미복용 → 담당 의사 알림"

④ MRT 적용 — 단일 채널 우선
   - 복약 알림: 음성 안내 (시각 자원이 다른 활동에 점유 중일 때)
   - 위급 알림: 시각(화면 깜빡임) + 청각(경고음) 이중 채널 동시 사용

⑤ 멘탈 모델 호환
   - 아날로그 달력 형태 UI, 기존 약통 모양 아이콘

경제·사회적 가치 논술 가이드

경제적 가치: 복약 오류 감소 → 재입원 감소 → 국민건강보험 재정 절감. 노인 의약품 부작용 관련 응급실 방문 비용 절감 (보건복지부 통계 인용).

사회적 가치: ① 독거노인의 자립 생활 연장 ② 노년층 디지털 헬스케어 접근성 향상 ③ 가족 안심: 원격 모니터링으로 고독사 예방.

인지공학 관점 마무리: "인지공학 원리를 반영한 설계는 단순 편의 향상이 아닌, 노년층의 인지 한계를 체계적으로 보완하여 자립 생활을 가능하게 한다"

문제 6 · 본인 성찰: 인지 변화 & 환경 최적화 (100점)

형식: 인지공학심리학 학습 후 본인의 인지적 변화와 업무/연구 환경 최적화 방안을 서술하는 성찰 문항이다. 단순히 "알게 되었다" 수준을 넘어 비판적 성찰이 필요하다. 각 항목마다 이론을 명시하고 실제 사례를 포함할 것.

문항 6-1. 이 수업을 통해 본인의 인지·지각·기억 방식에 대한 관점이 어떻게 변화하였는지 5개 이상 서술하시오. 이론(WM 한계, Bottom-up/Top-down, SEEV, Automaticity 양면성 등)을 명시하고 비판적 성찰을 포함. (50점)
문항 6-2. 학습한 인지공학 원리를 자신의 업무·연구 환경에 5개 이상 적용하여 최적화한 실제 사례 또는 계획을 서술하시오. 설계 원칙에 근거한 대안을 포함. (50점)
Q6는 정답이 없다 — 본인만의 구체 사례가 없으면 채점에서 손해. 아래 템플릿을 본인 경험으로 채워서 쓸 것. "알게 되었다" 금지, "이렇게 생각했는데 틀렸고 → 이렇게 바뀌었다"가 채점 핵심.

문항 6-1 전략 — 인지 변화 성찰 템플릿 (5개 이상)

★ 각 항목의 구조 ① 이전 생각 → ② 수업 후 인식 변화 → ③ 관련 이론 명시 → ④ 비판적 성찰 (기존 가정의 어느 부분이 틀렸는가)
항목 1 — WM 명제 한계: "집중하면 다 이해할 수 있다"는 믿음의 붕괴

이전: learnUs 공지나 긴 안내문을 한 번에 읽으면 다 이해할 수 있다고 생각했다.

변화: 문장 이해는 명제(proposition) 단위로 진행되며, 작업기억 용량은 약 4개 명제이다 (Kintsch & van Dijk, 1978). 4개 이상 앞 내용을 참조해야 하면 재활성화(reinstatement) 비용이 발생한다. 이후 긴 안내문은 명제 단위로 분할해 읽고, 핵심을 외부에 메모하는 방식으로 바꿨다.

비판적 성찰: "더 집중하면 된다"는 믿음은 WM의 명제 용량 제약을 고려하지 않은 것이었다. 시스템 설계 자체가 이 한계를 고려해야 하며, 사용자를 탓하는 것은 전형적 함정이다.

항목 2 — SEEV: 챗봇 알림 설계에서 경찰관이 왜 중요 정보를 놓치는지

이전: 피해자전담경찰봇 개발 시, 경찰관이 챗봇 알림을 무시하는 것은 "주의를 기울이지 않아서"라고 생각했다.

변화: SEEV 모델 — Salience(시각 돌출 부족), Effort(알림 아이콘 위치가 시선 중심에서 멀어 이동 비용 높음), Expectancy(평소 중요 알림이 드물어 기대 낮음), Value(이전 알림이 불필요했다는 경험으로 가치 낮음)가 모두 알림 무시를 설명한다.

비판적 성찰: "사용자 문제"를 "설계 문제"로 재해석하는 패러다임 전환. 경찰관을 탓하는 것이 아니라 Salience와 Value를 높이는 설계 변경이 정답이다.

항목 3 — Automaticity 양면성: 자동화는 언제 도움이 되고 언제 함정인가

이전: 반복적으로 하는 일(매일 논문 정리 루틴)은 익숙해질수록 좋다고 생각했다.

변화: 자동화(Unitization, Schneider & Shiffrin, 1977)는 고부하·스트레스 상황에서 강건하지만, 맥락이 바뀌면(새 플랫폼, 새 과제) 자동화된 반응이 오류를 유발한다. learnUs UI 업데이트 후 습관화된 탐색 경로가 반복 오류로 이어졌다.

비판적 성찰: 자동화는 효율의 도구이자 유연성의 적이다. 중요한 판단을 자동화에 맡기는 순간 변화에 대한 취약성이 커진다는 것을 인지공학이 체계적으로 설명해준다.

항목 4 — Bottom-up/Top-down: "읽는다"는 것이 이렇게 복잡한 과정이었나

이전: 논문을 이해 못하면 집중력 부족 탓이었다.

변화: Bottom-up과 Top-down의 상호작용을 이해하고 나서, 낯선 논문은 먼저 abstract와 conclusion을 읽어 Top-down 맥락을 먼저 활성화하는 전략으로 바꿨다 (Bransford & Johnson, 1972 — 맥락을 먼저 제공하면 이해·회상 모두 향상).

비판적 성찰: "집중력 부족"이 아닌 "Top-down 맥락 부재"가 진짜 원인이었다. 이 인식 변화는 학습 전략을 근본적으로 바꿨다.

항목 5 — FOR/FORT: "내가 이해하는 방향 = 청중이 이해하는 방향"이라는 착각

이전: 발표 슬라이드에 다이어그램을 그릴 때 내 시각(연구자 egocentric)에 맞춰 배치했고, 청중이 헷갈려 한다는 것을 이해하지 못했다.

변화: Frame of Reference 개념(Ch5, Wickens et al., 2022) — egocentric(발표자 기준)과 exocentric(청중 기준)이 다를 때 FORT(참조틀 변환) 비용이 발생한다. 90° 이상 불일치가 발생하면 좌우가 역전되어 오독이 급증한다. 이후 슬라이드 다이어그램은 청중의 시선 방향(Track-up 원리)에 맞게 재배치하기 시작했다.

비판적 성찰: "명확하게 그렸는데 왜 못 알아듣지?"의 답이 FOR 불일치였다. 설계자(발표자)의 참조틀이 사용자(청중)와 다르다는 것이 Ch4-5 전체의 핵심 교훈이기도 하다.

문항 6-2 전략 — 환경 최적화 사례 템플릿 (5개 이상)

★ 각 항목의 구조 ① 발견한 문제 → ② 적용한 인지공학 원리 + 인용 → ③ 실제 변화 (구체적 행동) → ④ 효과 또는 계획
사례 1 — PCP 적용: 논문 읽기 환경

문제: 논문(PDF)과 작성 중인 글(Word) 창을 왔다 갔다하며 주의가 분산되었다.

원리: 근접 호환성 원칙(PCP, Wickens & Carswell, 1995) — 동시에 통합해야 하는 정보는 디스플레이 상에서 근접하게 배치해야 한다.

변화: 듀얼 모니터에서 PDF(왼쪽) + 작성 문서(오른쪽)를 항상 동시에 표시. 단일 모니터일 때는 화면 분할 소프트웨어 사용.

사례 2 — Unitization: 새 도구 학습 시 일관된 매핑 우선

문제: Claude Code, Notion 등 새 도구를 쓸 때 기능마다 단축키·명령어가 달라 혼란스러웠고, 쓸 때마다 찾아봐야 했다.

원리: Unitization — 자동화는 일관된 반응 매핑(Consistent Mapping, Schneider & Shiffrin, 1977)이 있어야만 발달한다. 명령어가 맥락마다 바뀌면(Variable Mapping) 자동화가 불가능하다 (Ch6 §3.1).

변화: 도구마다 "핵심 3개 명령어"를 고정시키고 반복 사용. 다른 기능은 필요할 때만 추가 — Consistent Mapping 환경을 스스로 만들어 자동화 발달 유도.

효과: 반복 후 명령어를 의식적으로 생각하지 않게 됨 — 자동화 달성의 신호.

사례 3 — SA 외부화: 연구 타임라인 Kanban

문제: 연구 계획을 머릿속에서 관리하다 보니 마감을 놓치거나 우선순위를 혼동했다.

원리: "지식을 세상에 두기"(Norman, 1992) — WM 부담을 외부 표상으로 대체. SA Level 1-3을 보드가 지원.

변화: 논문별 진행 상태를 칸반(Notion)으로 시각화. "대기-진행 중-리뷰-완료" 4단계 분류.

사례 4 — SDT/Cry wolf 방지: 챗봇 알림 임계값 설계

문제: 피해자전담경찰봇 개발 시, 경찰관이 알림을 무시하지 않도록 임계값 설정이 고민이었다.

원리: SDT의 β 관리 — 오경보(False Alarm) 남발은 β를 보수적으로 이동시켜 진짜 위기도 무시하게 만든다 (Cry wolf syndrome, Wickens et al., 2022).

변화: 챗봇 알림을 Tier 1(즉각 개입 필요) / Tier 2(권고) / Tier 3(정보 제공)으로 3단계 분류. Tier 1은 절대 남발 금지. Likelihood Alarms 원리(Sorkin, 1989) 적용.

사례 5 — Complementarity + Spatial Contiguity: 연구 노트 재설계

문제: 텍스트만 빼곡한 연구 노트는 나중에 다시 읽을 때 이해가 느리고, 핵심 관계가 잘 보이지 않았다.

원리: Complementarity(Ch6 §6.2) — 텍스트와 그래픽이 서로 다른 정보를 제공할 때 두 채널의 이점을 모두 활용. Spatial Contiguity(Mayer) — 텍스트를 해당 그래픽 바로 옆에 배치해야 WM 통합 비용 최소화. 분리 형식보다 통합 형식이 이해 정확도 높음 (Tindall-Ford et al., 1997).

변화: 연구 노트에 개념도(concept map)와 텍스트를 통합 배치. 관련 수식·그림은 설명 텍스트 바로 옆에. weekly-textbook 스킬로 생성하는 보고서 레이아웃도 이 원칙 적용.

효과: 재독 시 이해 속도 향상, 발표 슬라이드 제작 시간 단축.
